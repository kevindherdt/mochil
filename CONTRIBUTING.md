# Contributing to Mochil

Mochil is written and maintained by one person, and for now it stays that way:
no code contributions are being accepted. That is not a judgement on anyone's
work — it is the only way to keep one coherent product instead of a pile of
opinions.

## What is genuinely welcome

**Bug reports.** Open an issue with:

- the version (footer of the web app, or `Settings → Diagnostics`),
- how you run it (Compose on which host, bare binary, NAS, Android, KOReader),
- what you expected, what happened, and the smallest way to reproduce it,
- the relevant lines from `docker compose logs` or the diagnostics page.

A report with a reproduction is worth ten without one, and each one gets read.

**Feature requests.** Describe the problem, not only the solution. "I cannot
find the book I was reading after switching libraries" is actionable; "add a
favourites bar" is a guess at the answer. Suggestions that add another setting
get extra scrutiny: this project prefers one good default over two mediocre ones.

**Translations, artwork, device testing.** If you have a KOReader device, a TV
box or an unusual NAS and want to check a release on it, say so in an issue.

## What happens to a pull request

It will be closed with a thank you and, if the idea is good, implemented by the
maintainer. If contributions ever open up, this file will say so first, and a
contributor licence agreement will be required so the project can stay
relicensable — that is what keeps paid support and dual licensing possible
without hunting down every contributor years later.

## Security

Do not open a public issue for a vulnerability. See [SECURITY.md](SECURITY.md).
